# سراج — نسخه تست v4

سامانه وب برای روشن‌کردن نیاز افراد: عضو نیاز را با صدا/متن ثبت می‌کند، AI (سمت سرور) آن را تحلیل می‌کند، ادمین (بازبین) سؤال‌ها را تأیید می‌کند، عضو پاسخ می‌دهد و در پایان «برگه روشن نیاز» با تأیید دوطرفه و نسخه PDF/چاپ تولید می‌شود.

**قانون ثابت:** هیچ خروجی AI بدون تأیید ادمین به عضو نمایش داده نمی‌شود — نه در UI و نه در پاسخ API (با تست سرور enforced است).

## معماری

- **Backend:** Express + Prisma + Postgres (پوشه `backend/`)
- **Frontend:** React + Vite + Tailwind — فارسی، RTL، موبایل‌محور، فونت وزیرمتن (پوشه `frontend/`)
- **AI:** فقط سمت سرور. مرورگر کاربر هرگز مستقیم به OpenAI وصل نمی‌شود.
- **فایل صوتی:** در دیتابیس ذخیره می‌شود (`webm/opus`، حداکثر ۳ دقیقه) — روی پلن رایگان Render با ری‌استارت دیسک پاک نمی‌شود.

## دیپلوی روی Render (پلن رایگان)

سریع‌ترین راه: **Blueprint** (فایل `render.yaml` در ریشه repo):

1. Repo را به GitHub پوش کنید.
2. در Render: New → Blueprint → این repo را انتخاب کنید.
3. مقادیر `sync: false` را پر کنید:
   - `OPENAI_API_KEY` — کلید OpenAI شما (از platform.openai.com)
   - `ADMIN_EMAIL` و `ADMIN_PASSWORD` — ورود ادمین (بازبین)
   - `PUBLIC_APP_URL` — آدرس frontend بعد از ساخت (مثل `https://seraj-web.onrender.com`) — پایه لینک‌های ورود اعضا
   - `VITE_API_BASE` — آدرس backend برای مرورگر (مثل `https://seraj-api.onrender.com`)
4. Deploy. بعد از بالا آمدن، در سرویس `seraj-web` مقدار `VITE_API_BASE` را با آدرس واقعی backend بگذارید و redeploy کنید (static site برای تغییر متغیر باید rebuild شود).

### رفتار سرور خوابیده

سرویس رایگان Render بعد از ۱۵ دقیقه بی‌استفاده می‌خوابد. فرانت‌اند وقتی سرور در حال بیدار شدن است پیام «سامانه در حال آماده‌سازی است، چند لحظه صبر کنید» نشان می‌دهد و خودکار دوباره تلاش می‌کند — کاربر صفحه خطا نمی‌بیند.

### اتصال دامنه اختصاصی

1. در Render: سرویس `seraj-web` → Settings → Custom Domains → Add Custom Domain → دامنه را وارد کنید (مثل `seraj.example.com`).
2. رکورد CNAME که Render نشان می‌دهد را در پنل DNS دامنه‌تان بسازید (مقدار معمولاً `seraj-web.onrender.com`).
3. برای backend هم اگر آدرس اختصاصی می‌خواهید: سرویس `seraj-api` → Custom Domains → همین کار.
4. بعد از تأیید SSL (چند دقیقه)، در Render: `seraj-web` → Environment → `VITE_API_BASE` را به آدرس جدید backend تغییر دهید و redeploy کنید. `PUBLIC_APP_URL` در `seraj-api` را هم به دامنه جدید frontend تغییر دهید (لینک‌های ورود اعضا از این متغیر ساخته می‌شوند).

### تنظیم کلید OpenAI

- در Render: سرویس `seraj-api` → Environment → `OPENAI_API_KEY` = کلید شما.
- متغیرهای دیگر (اختیاری): `OPENAI_BASE_URL` (پیش‌فرض `https://api.openai.com`)، `AI_CHAT_MODEL` (پیش‌فرض `gpt-4o-mini` — انتخاب مناسب برای تحلیل فارسی با هزینه کم)، `AI_TRANSCRIBE_MODEL` (پیش‌فرض `whisper-1` — پایدارترین مدل تبدیل گفتار فارسی).
- کلید هرگز در کد، repo، لاگ یا پاسخ API ظاهر نمی‌شود.

### ویرایش پرامپت‌ها

پرامپت‌ها فایل جدا هستند و بدون تغییر کد قابل ویرایش‌اند:
- `backend/prompts/analysis.md` — پرامپت تحلیل نیاز
- `backend/prompts/final-sheet.md` — پرامپت برگه نهایی

در Render: فایل را در repo تغییر دهید (یا با ادیتور Render) و redeploy کنید. ساختار خروجی JSON نباید تغییر کند.

### خروجی گرفتن از داده‌ها (پلن رایگان Postgres بعد از ~۳۰ روز منقضی می‌شود)

در Render: سرویس `seraj-api` → Shell:

```bash
node scripts/export-data.mjs /tmp/seraj-export
```

خروجی: یک JSON کامل از همه جدول‌ها + فایل‌های صوتی در پوشه `audio/`. آن‌ها را دانلود و نگهداری کنید.

برای انتقال به دیتابیس جدید، `DATABASE_URL` جدید را در Environment بگذارید، سرویس را redeploy کنید (migrate deploy خودکار اجرا می‌شود) و داده‌ها را با اسکریپت خروجی بازیابی کنید، یا مستقیم `pg_dump` بزنید:

```bash
pg_dump "$DATABASE_URL" > backup.sql
```

### ارتقا به پلن پولی (بدون تغییر کد)

1. `seraj-api`: Plan → **Starter** (بدون خوابیدن، always-on).
2. `seraj-db`: Plan → **Basic-256MB** یا بالاتر (ماندگار + بکاپ روزانه).
3. فرانت‌اند static site رایگان می‌ماند؛ تغییری لازم نیست.
4. برای انتقال داده‌های قدیمی: قبل از تغییر پلن، خروجی بگیرید (بخش بالا) و در دیتابیس جدید بازگردانید (`psql "$NEW_DATABASE_URL" < backup.sql`).

## متغیرهای محیطی

| متغیر | توضیح | پیش‌فرض |
|---|---|---|
| `OPENAI_API_KEY` | کلید OpenAI (الزامی برای AI) | — |
| `OPENAI_BASE_URL` | پایه API سازگار OpenAI | `https://api.openai.com` |
| `AI_CHAT_MODEL` | مدل تحلیل | `gpt-4o-mini` |
| `AI_TRANSCRIBE_MODEL` | مدل تبدیل گفتار | `whisper-1` |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | ورود ادمین (اولین ادمین خودکار ساخته می‌شود) | dev: `admin@seraj.local` / `seraj-admin-2026` |
| `JWT_SECRET` | امضای توکن‌ها | مقدار dev — روی Render تولید خودکار |
| `PUBLIC_APP_URL` | آدرس frontend — پایه لینک ورود اعضا | `http://localhost:3000` |
| `VITE_API_BASE` | آدرس backend برای مرورگر (build-time؛ در dev خالی = پروکسی) | proxy dev |

### Feature flags (همه پیش‌فرض خاموش — v4 MVP)

`FLAG_OTP`, `FLAG_PAYMENTS`, `FLAG_SESSIONS`, `FLAG_MENTOR_ASSIGNMENT`, `FLAG_AUTO_CLOSE_72H`, `FLAG_AUTO_DELETE_PROFILE` — مقدار `1` = روشن. کد امکانات قدیمی (OTP/پیامک، پرداخت، جلسه، منتور، بستن خودکار ۷۲ ساعته) در repo باقی است.

## اجرای محلی (Docker)

```bash
docker compose -f docker-compose.base44.yml up -d --build
# frontend: http://localhost:3000 — backend: http://localhost:4000
```

ورود ادمین پیش‌فرض dev: `admin@seraj.local` / `seraj-admin-2026` (حتماً با `ADMIN_EMAIL`/`ADMIN_PASSWORD` عوض کنید).

## جریان کار (v4)

1. ادمین عضو را با نام و شماره می‌سازد → لینک ورود ۳۰روزه (قابل باطل‌کردن) + پیام آماده واتس‌اپ.
2. عضو در اولین ورود رضایت می‌دهد.
3. عضو نیاز را ضبط می‌کند (≤۳ دقیقه) یا می‌نویسد → صدا سمت سرور به متن فارسی تبدیل می‌شود → عضو متن را اصلاح/تأیید می‌کند (فقط متن تأییدشده وارد پرونده می‌شود؛ صدای اصلی برای ادمین قابل پخش است).
4. تحلیل AI ناهمزمان اجرا می‌شود («در حال تحلیل») و خروجی فقط در پنل ادمین ثبت می‌شود: خلاصه، اطلاعات ناقص، حداکثر ۵ سؤال، وضعیت ۵ بخش شفافیت.
5. ادمین هر سؤال را تأیید/ویرایش/حذف می‌کند یا دستی اضافه می‌کند → «ارسال» فقط سؤال‌های تأییدشده را به عضو می‌رساند.
6. عضو با صدا/متن پاسخ می‌دهد (همان تبدیل و تأیید) → تحلیل دوباره اجرا می‌شود → دور بعد یا پیشنهاد جمع‌بندی.
7. برگه نهایی: پیش‌نویس AI (۵ بخش + فهرست اطلاعات ناقص) → ادمین ویرایش و تأیید → عضو مشاهده و تأیید → دریافت نسخه PDF/چاپ (فارسی، RTL).
8. نظرسنجی ۱–۵ + یک جمله. ادمین پرونده را دستی می‌بندد.
